Proactive AI Job Notifications

Concept demo — not wired into the real backend yet. Review here first.

1. Design overview

Right now, get_recommended_jobs(worker) only runs when a worker clicks "Find Jobs for Me" (pull). This turns the same scoring logic into a push: the moment a household posts a new open job, the backend scores that one job against every candidate worker and creates a Notification for anyone above a match threshold — before the worker ever opens the app.

  • Trigger: a Django post_save signal on JobPosting, firing only when a new row is created with status="open".
  • Reused logic: the per-job/per-worker scoring math is extracted out of get_recommended_jobs() into a shared score_job_for_worker(job, profile) function, so the pull endpoint and the new push signal always agree on what counts as a good match.
  • Threshold: only workers scoring above NOTIFY_THRESHOLD (e.g. 0.5) get notified — otherwise every new job would spam every worker.
  • Radius still hard-filters first — exactly like the pull endpoint, a job outside a worker's reach never reaches the scoring step at all.

3. Backend sketch

backend/apps/matching/recommendations.py (refactor)
# Extracted from get_recommended_jobs() so both the pull endpoint and the
# new push signal use the exact same scoring math.
def score_job_for_worker(job, profile):
    worker_document = _worker_skill_document(profile)
    job_document = _job_skill_document(job)
    if not worker_document.strip():
        return None

    vectorizer = TfidfVectorizer()
    tfidf_matrix = vectorizer.fit_transform([worker_document, job_document])
    skill_similarity = cosine_similarity(tfidf_matrix[0:1], tfidf_matrix[1:2])[0][0]

    route = get_road_route_for_match(job, profile)
    distance_km = route["distance_km"]
    if not _within_radius(job, distance_km):
        return None

    proximity_score = _proximity_score(distance_km)
    ai_score = (float(skill_similarity) * SKILL_WEIGHT) + (proximity_score * PROXIMITY_WEIGHT)
    return {"ai_score": round(ai_score, 4), "distance_km": distance_km}
backend/apps/matching/signals.py (new)
NOTIFY_THRESHOLD = 0.5

@receiver(post_save, sender=JobPosting)
def notify_matching_workers(sender, instance, created, **kwargs):
    if not created or instance.status != JobPosting.STATUS_OPEN:
        return
    candidates = UserProfile.objects.filter(role=UserProfile.ROLE_WORKER)
    for profile in candidates:
        result = score_job_for_worker(instance, profile)
        if result and result["ai_score"] >= NOTIFY_THRESHOLD:
            Notification.objects.create(
                user=profile.user,
                notification_type="job_match",
                title="New job matches your profile",
                body=f"{instance.title} — {round(result['ai_score'] * 100)}% match",
                related_job=instance,
            )
Runs synchronously inside the request that creates the job for this sketch. In production this loop should move to a Celery task (or similar) so posting a job doesn't wait on scoring every candidate worker.
